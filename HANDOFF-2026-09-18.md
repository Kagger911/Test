# kagchat on K3s — deployment record and handoff

**Cluster:** Sleep Deprivation Station K3s (v1.36.x, containerd), 1 control plane + 7 workers
**Window:** 2026-09-17 14:00 → 2026-09-18 01:30 MDT
**Repos:** `Kagger911/Test` (branch `claude/erebus-docker-build-l5bm8z`) — chat and cluster tooling; `Kagger911/sleepdeprivationstation` (`master`) — public site
**Identifiers:** node IPs, tunnel ID, SSH user and key paths live in the encrypted vault (`./vault.sh unlock` → `private/station.env`). This document uses node names only.

---

## 1. Executive summary

We moved **kagchat**, an end-to-end encrypted chat relay, from a single `docker-compose` stack on the control-plane node (erebus) onto the K3s cluster, pinned to the four arm64 Khadas VIM3 workers, and fronted it through the existing Cloudflare tunnel plus a new Tor onion service. We added a private image registry, a one-command build-and-roll pipeline, node-failure tolerations, readiness gated on Redis, and a hardened relay (hashed CSP, build attestation) in response to a community security review. As a side fix we gave the cluster's Grafana persistent storage; it had been losing all state on every pod restart. All changes are live; the relay survived a scripted kill of a relay pod and of Redis with no manual intervention.

### Deleted / retired

- The `docker-compose` stack (`kagchat-relay-1`, `kagchat-redis-1`, network `kagchat_default`) on erebus — `docker compose down` after the cluster served production traffic. It remains a documented fallback.

### Application changes that shipped in the image

Not cluster objects, but they define what the pods do:

- **Relay (Go):** waits for Redis at startup instead of exiting; `/healthz` returns 503 while Redis is unreachable (readiness); `/version` returns the build commit; security headers including a Content-Security-Policy whose `script-src`/`style-src` are SHA-256 hashes of the shipped `<script>`/`<style>` blocks (no `unsafe-inline`); `Onion-Location` header when `ONION_ADDR` is set; `X-Kagchat-Build` header.
- **Client (single HTML file):** signatures now cover the room id; replay guard; build tag in the footer; recent-rooms list, room names, unread count, notification tone, intro sound, key rotation, station skin. Inline `style=` attributes removed so the hash-based CSP holds.
- **Image:** multi-stage Dockerfile; the Go stage runs on `$BUILDPLATFORM` with `GOARCH=$TARGETARCH`, so arm64 is a native cross-compile — **no QEMU/binfmt needed**; `ARG BUILD` baked in via `-ldflags "-X main.build=…"`.

## 3. Step-by-step implementation

Times are MDT. Commits are on `Kagger911/Test` unless noted.

### 3.1 Baseline on erebus (14:28–16:16) — commits `79b0342` … `ad3920a`

1. Imported the project into git so erebus could `git clone` instead of receiving files by hand.
2. Fixed three defects before first run: the Dockerfile built on `golang:1.23` while `go.mod` required 1.24 (the official image pins `GOTOOLCHAIN=local`, so the build fails outright); `depends_on` did not wait for Redis (the relay `log.Fatalf`s without it); host port 8080 collides with Pi-hole on erebus, so the compose port became 8081.
3. Ran the compose stack, exposed it through the tunnel (`localhost:8081`), and iterated on the client. **Rationale:** prove the application on one box before adding scheduling, registries and cross-arch builds to the problem.

### 3.2 Cluster move (16:27–20:14) — commits `ba47a7e`, `12ac557`, `672370c`

4. **Registry.** Chose a private `registry:2` container on erebus over ghcr.io: no tokens, no internet round-trip for the boards, image stays on the LAN. Boards trust it through `registries.yaml` (`k8s/registries.yaml.tmpl`).
5. **Board prep** (`k8s/prep-boards.sh`): for each VIM3 over SSH — install `registries.yaml`, restart `k3s-agent`, open flannel/kubelet/NodePort in ufw *if* ufw is active (it was not), then `kubectl label node … sds.role=chat`. Idempotent; exits non-zero if any board fails so the caller stops before deploying to a half-prepared cluster.
6. **Build pipeline** (`k8s/deploy.sh`): `docker buildx build --platform linux/amd64,linux/arm64 --push`, `kubectl apply`, `rollout restart deploy/relay`, `rollout status`, then `curl /healthz` on the NodePort. **Rationale for `imagePullPolicy: Always` + `rollout restart`:** the tag is `latest`; without both, a rollout would reuse the cached image.
7. **Incident during first push:** BuildKit timed out dialing the registry (`dial tcp …:5000: i/o timeout`) and used `https://`. Two causes: ufw on erebus dropped traffic from Docker's bridge to host ports, and newer buildx renamed `--config` to `--buildkitd-config`, so the "registry is http" file was never read. **Fix (`672370c`):** builder recreated with `--driver-opt network=host`; try `--buildkitd-config` then fall back to `--config`; `ufw allow … port 5000` from the LAN. Push then completed in 0.1 s.
8. **Cut-over** (`k8s/move.sh`): registry → boards → deploy → verify `/healthz` = 200 → *only then* `sed` the cloudflared ingress to `localhost:30080` and restart it. The compose stack kept running throughout, so a failed step changed nothing for users.
9. Retired the compose stack with `docker compose down` after browser verification.

### 3.3 Security hardening (20:33, 00:43) — commits `985fbd4`, `57d3054`

10. A community review of the served client raised: injected third-party scripts (Cloudflare Web Analytics was in fact injecting `beacon.min.js` into the chat page), cross-room signature reuse, replay, client trust, forward secrecy.
11. Relay changes: CSP + security headers on every file-server response; `/version` + `X-Kagchat-Build` from `--build-arg BUILD=$(git rev-parse --short=12 HEAD)`; readiness stays as-is here.
12. Client changes: room id in the signed form; per-session signature dedup.
13. Second pass: replaced `'unsafe-inline'` with SHA-256 hashes computed by the relay at startup from `web/index.html`; removed inline `style=` attributes the hash policy would block.
14. Cloudflare dashboard (manual): Web Analytics automatic injection **off**; Page Rule on `chat.…/*` disabling Rocket Loader, Email Obfuscation, Browser Integrity Check.

### 3.4 Onion service (21:20) — commit `9a3e793`

15. `k8s/onion.sh`: install `tor`, append a `HiddenServiceDir`/`HiddenServicePort 80 127.0.0.1:30080` stanza, wait for the hostname, `kubectl set env deploy/relay ONION_ADDR=<addr>`. `deploy.sh` re-applies `ONION_ADDR` from the tor hostname file so a later `apply` never drops it. **Rationale:** the clearnet path necessarily exposes client IPs to Cloudflare; a v3 onion is the only mechanism that removes that, and it reuses the same NodePort.

### 3.5 Failover behaviour (23:07) — commit `6674fa3`

16. **Problem:** default node tolerations keep pods on an unreachable node for 300 s; a relay that could not reach Redis crash-looped into a growing backoff; readiness always returned 200.
17. **Changes:** tolerations `node.kubernetes.io/unreachable` and `not-ready` with `tolerationSeconds: 20` on both Deployments; relay polls Redis every 2 s at startup instead of `log.Fatalf`; `/healthz` pings Redis with a 2 s timeout and returns 503 on failure; readiness probe `periodSeconds: 5`, `failureThreshold: 2`; `PodDisruptionBudget relay minAvailable: 2`.
18. `k8s/failover-test.sh` deletes one relay pod, then the Redis pod, printing ready counts and NodePort `/healthz` every 2 s until recovery.

### 3.6 Grafana persistence (15:58) — `helm upgrade monitoring … rev 3`

19. **Problem:** `monitoring-grafana` mounted `storage` as `emptyDir`; 12 restarts in 21 days, each wiping bookmarks, UI-built dashboards and users.
20. **Change:** `helm upgrade monitoring prometheus-community/kube-prometheus-stack --version 88.5.4 -n monitoring --reuse-values --set grafana.persistence.enabled=true --set grafana.persistence.type=pvc --set grafana.persistence.size=5Gi --set grafana.persistence.storageClassName=local-path --set grafana.deploymentStrategy.type=Recreate`. **Rationale:** `local-path` over `nfs-shared` because Grafana's SQLite database is unsafe on NFS; `Recreate` so two pods never contend for the RWO volume. Trade-off: Grafana is now pinned to the node that first bound the PV.

### 3.7 Documentation and secrets (00:47–01:21) — commits `eff116b`, `5be9f96`, `7cf1c18`

21. Wrote `STATION.md` (public: architecture, runbooks) and moved every identifier into `private/STATION-PRIVATE.md` + `private/station.env`.
22. Parameterised all scripts through `k8s/station-env.sh`, which refuses to run without `private/station.env`; `registries.yaml` and `buildkitd.toml` became templates rendered at run time; the manifest image is `${REGISTRY}/…` filled by `sed` in `deploy.sh`.
23. `vault.sh lock|unlock|list`: AES-256-CBC, PBKDF2 600k iterations, `tar`+`openssl` only. `lock` on erebus also captures the Tor key and cloudflared credentials/config. `station.vault` is committed; `private/` is gitignored. Fails closed on a wrong passphrase (`set -o pipefail`).

## 5. Potential impact and next steps

### Follow-up actions (ranked)

1. **Erebus is a single point of failure** — control plane, tunnel, Tor, registry and LAN DNS. Run a **second cloudflared connector on another amd64 worker** with the same tunnel credentials (Cloudflare balances across connectors; `localhost:30080` works on any node). Makes chat and Kagflix survive an erebus outage.
2. **Image tags.** The manifest uses `:latest` + `Always`, so `kubectl rollout undo` re-pulls the *same* new image and does not roll back code. Have `deploy.sh` also tag `${REGISTRY}/kagchat:<commit>` and reference that tag in the manifest; then `rollout undo` is a real rollback.
3. **cert-manager** Helm release is in `failed` state (install never completed). Nothing depends on it; `helm uninstall` or finish it before something does.
4. **Grafana PVC** has no off-node backup and pins Grafana to one node. Periodic `kubectl cp` of `/var/lib/grafana/grafana.db`, or move to a backed-up class.
5. **Public repo history** still contains the unscrubbed `STATION.md` (commit `eff116b`) and script versions with LAN IPs. Either make `Kagger911/Test` private or rewrite the branch history (force-push; re-clone on erebus).
6. **SSH on erebus** answers on the public IPv6 address as well as the LAN. Restrict with `ufw allow from <LAN>/24 to any port 22 proto tcp` and remove the open rule; consider key-only auth.
7. **Redis is one pod** (accepted: memory-only, 24 h TTL, seconds to move).
8. The `Test` repo pushes from erebus need a GitHub fine-grained token (`Contents: read/write` on `Test`) with `git config credential.helper store`; today's vault push went through an upload instead.

### Metrics to watch (Grafana: Node Exporter Full `1860`, Kubernetes Views / Pods `15760`)

- `kube_pod_container_status_restarts_total{namespace="kagchat"}` — relays should not restart; Redis restarts mean scrollback loss.
- Readiness flaps on `relay` — `/healthz` 503 means Redis unreachable.
- Redis memory vs `maxmemory` 256 Mi — `allkeys-lru` sheds oldest rooms silently when full.
- Node `Ready` for the four boards; with 20 s tolerations a flapping board causes pod churn.
- `kube_persistentvolumeclaim_status_phase{persistentvolumeclaim="monitoring-grafana"}` and volume usage.
- NodePort `/healthz` from erebus (cloudflared's target); the site's chat page also polls it live.

### Rollback procedures

| Scenario | Action |
|---|---|
| Bad relay build | `sudo kubectl -n kagchat rollout undo deploy/relay` **only rolls back after item 2 above is done**. Today: `git checkout <good-commit> -- kagchat/` then `./k8s/deploy.sh`. |
| Cluster path broken, need service now | On erebus: `cd ~/test/kagchat && docker compose up -d` (host port 8081), then `sudo sed -i 's|localhost:30080|localhost:8081|' /etc/cloudflared/config.yml && sudo systemctl restart cloudflared`. Reverse the `sed` to return. |
| Onion misbehaving | `sudo systemctl stop tor`; `sudo kubectl -n kagchat set env deploy/relay ONION_ADDR-` (removes the `Onion-Location` header). Key stays in `/var/lib/tor/kagchat/` and in the vault. |
| Grafana | `helm rollback monitoring 2` returns to `emptyDir` (loses persistence — avoid); to move the PV, back up `grafana.db` first. |
| Registry lost | Recreate the container (`docker run … registry:2`), rerun `./k8s/deploy.sh`; boards re-pull on the next rollout. |
| Board re-imaged | Join to K3s, `./k8s/prep-boards.sh`, `./k8s/deploy.sh`. |
